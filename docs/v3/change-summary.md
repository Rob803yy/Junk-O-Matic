# What carries forward from V2 into assisted V3

The design target is an instrumented RC hauler with camera-based litter detection and operator-facing advice. Motion stays under manual RC. Carry-forward intent does not confirm an untraced connection, measured dimension, selected Pi model or deployed program.

## Component decisions that do not follow automatically from V3

Keep the SCX6/cart/mounting concept and owner-confirmed member/hinge relationships. Retain Uno R3 as the acquisition MCU. Benchmark the existing Pi before selecting a replacement. The one-camera starting design and camera mount are proposals; camera model/interface/supply and actual count are unselected.

GPS/RTK, LiDAR, encoders, PWM boards, robotic arms, powered intake, dual bins, RC handoff and computer motion control are not required by this assisted scope. Dedicated voltage/temperature hardware or compute/cooling/storage changes may be justified by later evidence; no purchase, rating or fabricated measurement is selected here.

Uno R3 board identity, vehicle V3, firmware build ID and serial protocol 2 are separate version fields. New visual advisories do not require a new Uno serial format or a Pi-to-Uno command channel.

BOM/scorecard/review-system/Word outputs will be new V3 derivatives after choices and evidence are reviewed. Existing corrected workbooks, historical annotated documents and archived PDFs remain unchanged. The current planning workbook describes those changes; the named future native/Office artifacts have not been generated.

All existing files are covered in the file register. Archive contents remain historical, previous test receipts stay at their original revision, and the license entry is explicitly unreviewed.
